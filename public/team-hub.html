Build Queue — How It Works

The single source of truth for what needs to be built.

1

Bryan adds tasks after every meeting

AI processes the transcript. Tasks are auto-created in Google Sheets with priority, system type, and auto-assigned builder.

2

Pull from the queue — highest priority first

Don't wait for Bryan to personally assign you. See a high-priority task in your lane? Grab it.

3

Change status to "In Progress"

This prevents duplicate work. If someone sees "In Progress" with your name, they know you're on it.

4

Build it. Post "Done" + update.

Change status to "Done" in the sheet. Post a 1-line summary in the group chat.

5

Blocked? Change to "Blocked" immediately

Don't sit on a blocker. Post in group chat what you need. Move to the next task.

Do NOT

X Wait for Bryan to personally assign you a task from the queue — pull it yourself
X Work on low-priority items when high-priority items exist
X Start a task without updating the status (prevents duplicate work)

Communication Rules

How we talk. Where we talk. What we don't do.

Post updates in group chat

Everyone stays in the loop. Bryan doesn't become a bottleneck. The group chat is the system of record.

Don't DM Bryan

Questions in group chat so everyone sees the answer. No private threads. No bottlenecks.

Flag blockers immediately

Don't sit on a blocker for hours. Post: "Blocked on [X] — need [Y] to continue."

Don't message Bryan 11am-5pm

He's off. Handle it yourself or ask Lee/Vee. Only exception: client system is down.

Handoff notes are mandatory

Shift ends? Leave a note: what's done, what's next, any gotchas. 2 minutes. Every time.

Don't message clients directly

All client comms go through Bryan. If a client messages you, forward to Bryan. Don't respond.

Standard Operating Procedures

9 SOPs. Follow every one. Every day.

When you clock in, do these 3 things FIRST:

1
Check the Build Queue

Open the Google Sheet for your assigned client(s). See what's high priority.

2
Read the group chat

Scroll up to the last handoff note and any new messages from Bryan. Don't miss context.

3
Update your status

Post in the group chat: "Clocked in. Starting on [task name]."

Then start building.

Before you start:

  • Change the task status to "In Progress"
  • Make sure no one else is already working on it (check "Assigned To" column)

While you work:

  • Need access, logins, or context — message the group chat immediately, don't wait
  • Hit a blocker — post it: "Blocked on [X]. Need [Y] from [person]."
  • Task takes longer — post: "Still working on [X]. ETA: [time]."

When you finish:

  • Change status to "Done"
  • Post in group chat: "[Task name] — done. [1-line summary]."
  • If it needs QA, change to "Ready for QA" and tag Lee

Mandatory. Before you log off, post this in the group chat:

After every client meeting, Bryan posts a task list in the group chat.

1
Read all tasks — understand the full picture, not just individual items
2
Check priorities — Bryan marks High / Medium / Low. Start with High.
3
Claim your tasks — Update Build Queue: set "Assigned To" = your name, status = "In Progress"
4
Start immediately — no waiting for Bryan to confirm. If he posted it, it's approved.
5
Ask questions in the group chat — not in DMs to Bryan. Everyone should see the answer.

When a build is marked "Ready for QA":

1
Open the build — log into the client's system and test it
2
Run through this checklist:
Does it work?Click every button, test every flow, trigger every automation
Does it match?Compare what was built to what Bryan requested
No errors?Check for broken links, missing fields, error messages
Client-ready?Would you show this to the client right now? If no, send it back.
3
If pass: Change status to "Done". Post: "QA passed on [task]."
4
If fail: Change status to "QA Failed." Post what's wrong and send back to builder.
